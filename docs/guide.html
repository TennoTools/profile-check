Guide

From first install to the local API — everything the README knows, on one page.

First run

the /init wizard

No terminal skills? Windows: double-click launch.bat — Linux/macOS: ./launch.sh (first time only: chmod +x launch.sh). It installs, builds and starts everything, then opens your browser — press Q in the launcher window to stop it.

  1. The /init wizard — with nothing configured yet, every app page redirects to a standalone first-run screen (no nav): paste your ScraperAPI key (optional), find your AccountId with Find my Account ID (temporary Chromium, manual login, nothing stored) — or press Try with the sample account to test the pipeline on [DE]Rebecca's public profile. Saving a key or an id leaves the wizard for good (skipping unlocks the app for the session and re-proposes it next session).
  2. Check — Find & run finds your AccountId and launches the check as soon as it is found; you can also Paste a known 24-hex id or reuse the saved one. The finder alone lives in Settings.
  3. Watch the live progress (SSE) and read the verdict; each run is kept in History.

What a check does

one request, five steps
  1. Fetch — exactly one HTTP request to https://api[-<platform>].warframe.com/cdn/getProfileViewingData.php?playerId=<id> (pc uses api.warframe.com; consoles use api-ps4|x-xb1|api-swi|api-mob|api-and). With a ScraperAPI key, a network-level failure triggers a single retry through the proxy (direct → scraperapi-fallback). HTTP error statuses are never retried.
  2. Parse — new ProfileParser(data, 'en', withItem=false).
  3. Validate — the 13 frozen checks (6 critical), run through a safe wrapper (an exception becomes a failed check) — full list and rules.
  4. Verdict — any critical fail → broken; only non-critical fails → warnings; else ok.
  5. Persist — summary + checks + request metadata in data/app.sqlite.

Configuration

.env is a bootstrap only

.env at the repo root is read once at startup; missing keys are seeded into the settings DB, and the GUI is the source of truth afterwards.

KeyMeaning
SCRAPERAPI_KEYoptional proxy key
WARFRAME_ACCOUNT_IDyour AccountId, used as the default in the GUI

Environment overrides: TENNOTOOLS_HOST (default 127.0.0.1), TENNOTOOLS_PORT (default 8787), TENNOTOOLS_DB_PATH (default data/app.sqlite).

Never upload the database. Run history lives in data/app.sqlite (SQLite, WAL mode); while the server runs, recent rows may still be in app.sqlite-wal — stop the server or run npm run db:checkpoint before opening the file in a viewer. The settings table holds your ScraperAPI key in clear text.

Rules of engagement

hard-won
  • The only working endpoint is api[-<platform>].warframe.com/cdn/getProfileViewingData.php?playerId=; DE removed the old nickname endpoint — a nickname alone can no longer fetch a profile.
  • The profile must be viewable in game (Esc → Options → Social → profile viewing), otherwise DE answers 500 even for a valid id.
  • DE caches responses — the run page shows XpCacheExpiryDate; wait for expiry before retrying.
  • AccountIds are MongoDB ObjectIds: 24 hex chars whose first 4 bytes are a creation timestamp — that is what looksLikeAccountId checks (2012 → now + 1 year).
Do not spam the API. Excessive calls can temporarily ban your IP, which also blocks game login. One request per run is all this tool ever does (plus at most one ScraperAPI fallback).
